# v1.2a — Authorization Spine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace ~40 copy-pasted `req.user.role !== 'admin'` checks with a capability kernel, and add the `super_admin` / `partner` roles, without breaking a single one of the 508 existing tests.

**Architecture:** A pure-logic capability module (`server/authz.js`) maps roles to named capabilities; a `requireCap()` middleware becomes the only authorization primitive in route files. Adding roles requires rebuilding the `users` table because SQLite cannot alter a CHECK constraint, so a versioned migration registry lands first to make that rebuild testable and idempotent. A generated routes × roles matrix test locks the resulting behaviour in place.

**Tech Stack:** Node 24, `node:sqlite` (`DatabaseSync`), Express, vitest, React 19 + react-router 7.

**Why this ships before every other v1.2 workstream:** step-up auth (v1.2b) and error capture (v1.2c) both gate on capabilities that do not exist yet. See [the master plan §3](2026-07-31-v2-platform-master-plan.md).

## Global Constraints

- **Timestamps:** ISO-8601 UTC generated in JS (`new Date().toISOString()`). **Never** SQLite `datetime('now')` — it returns a space-separated string and breaks lexicographic comparison (TD-10).
- **Booleans:** SQLite `INTEGER` 0/1. **Ids:** `TEXT` (`crypto.randomUUID()`).

- **Error envelope:** `res.status(n).json({ error: 'message' })`. 401 = not authenticated; 403 = authenticated but not permitted.
- **Lint:** `npm run lint` must report zero warnings (`.oxlintrc.json` baseline).
- **Commits:** conventional prefixes (`feat:`, `fix:`, `test:`, `refactor:`, `chore:`). Commit at the end of every task.
- **Design tokens (client tasks):** no hardcoded colors, no dangling class names — `noHardcodedColors.test.js`, `tokens.test.js`, and `noDanglingClasses.test.js` enforce this and will fail the build.

`server/migrations/index.js`:

```js
/**
 * Ordered, versioned schema migrations.
 *
 * db.js keeps its `CREATE TABLE IF NOT EXISTS` + addColumnIfMissing() bootstrap
 * for the tables that predate this registry — rewriting that is risk with no
 * reward. Everything structural from v1.2 onward goes here instead, because the
 * next few changes are table REBUILDS (SQLite cannot alter a CHECK constraint)
 * and those need ordering, a record of what already ran, and a rollback story.
 */
import authzRoles from './001_authz_roles.js';
import userCapabilities from './002_user_capabilities.js';

export const MIGRATIONS = [authzRoles, userCapabilities];

const label = (m) => `${m.version}_${m.name}`;

function ensureBookkeeping(db) {
  db.exec(`
    CREATE TABLE IF NOT EXISTS schema_migrations (
      version    INTEGER PRIMARY KEY,
      name       TEXT NOT NULL,
      applied_at TEXT NOT NULL
    )
  `);
}

export function appliedVersions(db) {
  ensureBookkeeping(db);
  return db.prepare('SELECT version FROM schema_migrations ORDER BY version').all().map(r => r.version);
}

/**
 * Applies every migration not yet recorded, lowest version first.
 *
 * Each migration runs inside its own transaction so a failure leaves the
 * database exactly as it was — including the schema_migrations row, which is
 * written inside the same transaction as the DDL it describes. A migration that
 * manages its own transaction (the table rebuilds must, because
 * `PRAGMA foreign_keys` cannot change inside one) sets `ownTransaction = true`.
 */
export function runMigrations(db, migrations = MIGRATIONS) {
  ensureBookkeeping(db);

  const seenVersions = new Set();
  for (const m of migrations) {
    if (seenVersions.has(m.version)) {
      throw new Error(`Duplicate migration version ${m.version} (${m.name})`);
    }
    seenVersions.add(m.version);
  }

  const ordered = [...migrations].sort((a, b) => a.version - b.version);
  const already = new Set(appliedVersions(db));
  const applied = [], skipped = [];

  for (const m of ordered) {
    if (already.has(m.version)) { skipped.push(label(m)); continue; }

    const record = () => db.prepare(
      'INSERT INTO schema_migrations (version, name, applied_at) VALUES (?, ?, ?)'
    ).run(m.version, m.name, new Date().toISOString());

    try {
      if (m.ownTransaction) {
        m.up(db);
        record();
      } else {
        db.exec('BEGIN');
        try { m.up(db); record(); db.exec('COMMIT'); }
        catch (err) { db.exec('ROLLBACK'); throw err; }
      }
      console.log(`Migration applied: ${label(m)}`);
      applied.push(label(m));
    } catch (err) {
      throw new Error(`Migration ${label(m)} failed: ${err.message}`, { cause: err });
    }
  }

  return { applied, skipped };
}
```

`server/authz.js`:

```js
/**
 * Capability-based authorization.
 *
 * Before this module, authorization was ~40 copies of `req.user.role !== 'admin'`
 * spread across route files. That pattern has one fatal property: adding a role
 * silently DENIES it everywhere, because 'super_admin' !== 'admin' is true. The
 * platform owner would have been locked out of every admin route, and no test
 * would have failed.
 *
 * Route files now ask for a named capability and never look at a role string.
 * `authz.completeness.test.js` enforces that.
 *
 * This module is pure: it imports nothing from db.js, so it is unit-testable
 * with no fixtures and cannot decay into a data-access layer.
 */

export const ROLES = ['student', 'organizer', 'admin', 'super_admin', 'partner'];

export const CAPABILITIES = {
  student: [
    'event.view', 'event.apply', 'application.withdraw',
    'self.read', 'self.write', 'portfolio.write', 'message.send', 'qr.present',
  ],
  organizer: [
    'event.view', 'event.create', 'event.edit.own', 'applicant.review',
    'attendance.mark', 'attendance.scan', 'announcement.post',
    'message.send', 'self.read', 'self.write', 'service.verify.own_event',
    'geocode.use',
  ],
  admin: [
    'event.view', 'event.moderate', 'organizer.approve', 'user.suspend',
    'report.resolve', 'audit.read', 'analytics.school',
    'service.verify.external', 'capability.grant',
    'attendance.mark', 'attendance.view',
    'self.read', 'self.write', 'geocode.use',
  ],
  super_admin: ['*'],
  partner: ['analytics.public'],
};

/**
 * Capabilities only super_admin may hold.
 *
 * Declared explicitly rather than left implicit under the '*' wildcard, because
 * `can()` refuses any capability not named somewhere in this file. Without this
 * list a typo ('error.raed') would resolve TRUE for super_admin and 403 for
 * everyone else — the worst kind of authorization bug, because it looks like it
 * works when the person testing it is the owner.
 */
export const SUPER_ONLY = [
  'error.read', 'error.write',
  'analytics.platform',
  'impersonation.start',
  'admin.create',
];

export const ALL_CAPABILITIES = [...new Set([
  ...Object.values(CAPABILITIES).flat().filter(c => c !== '*'),
  ...SUPER_ONLY,
])].sort();

const CAPABILITY_SET = new Set(ALL_CAPABILITIES);
const SUPER_ONLY_SET = new Set(SUPER_ONLY);

/**
 * Builds the request principal from a users row.
 *
 * `effectiveRole` is separate from `actualRole` so impersonation (v2.0) is a
 * change of the effective role only — never a second role on the account.
 */
export function principalFor(userRow, { grants = [], aal = 1, actorId = null, effectiveRole = null } = {}) {
  if (!userRow) return null;
  return {
    userId: userRow.id,
    actualRole: userRow.role,
    effectiveRole: effectiveRole || userRow.role,
    actorId,
    grants,
    aal,
    impersonating: Boolean(actorId),
  };
}

/** Deny-by-default authorization decision. */
export function can(principal, capability) {
  if (!principal || !capability) return false;
  if (!CAPABILITY_SET.has(capability)) return false;   // unknown/typo → deny, always

  const role = principal.effectiveRole;
  if (!ROLES.includes(role)) return false;

  const roleCaps = CAPABILITIES[role] || [];
  if (roleCaps.includes('*')) return true;             // super_admin
  if (roleCaps.includes(capability)) return true;

  // Per-user grants (Task 4) extend a role, but can never reach a super-only
  // capability — otherwise `capability.grant` would be a path to root.
  if (SUPER_ONLY_SET.has(capability)) return false;
  return Array.isArray(principal.grants) && principal.grants.includes(capability);
}
```

### Task 3: `users` table rebuild — add `super_admin` and `partner`

**This is the highest-risk task in the entire v2 program. Read all of it before running anything.**

`users.role` has a `CHECK(role IN ('student','organizer','admin'))` constraint.
SQLite cannot alter a CHECK, so the table must be rebuilt. Two properties make
this dangerous:

1. **`node:sqlite` enables foreign keys by default** (`dataIntegrity.test.js:210`
   asserts `PRAGMA foreign_keys` is `1`). At least 15 tables reference
   `users(id)` with `ON DELETE CASCADE`. **`DROP TABLE users` with foreign keys
   ON would cascade-delete essentially the entire database.** `PRAGMA
   foreign_keys = OFF` is not an optimization here; it is the difference between
   a migration and a data-loss incident.
2. **`PRAGMA foreign_keys` is a no-op inside a transaction.** It must be set
   before `BEGIN`. That is why this migration declares `ownTransaction = true`.

**Files:**
- Modify: `server/migrations/001_authz_roles.js` (replace the Task 1 placeholder)
- Create: `server/migrations.authzRoles.test.js`

**Interfaces:**
- Consumes: `runMigrations` (Task 1).
- Produces: `users.role` accepting `'super_admin'` and `'partner'`; exports `EXPECTED_USER_COLUMNS: string[]` for the guard test.

`server/migrations/001_authz_roles.js`:

```js
/**
 * Adds 'super_admin' and 'partner' to users.role.
 *
 * SQLite cannot alter a CHECK constraint, so the table is rebuilt. Two hazards
 * govern the shape of this code:
 *
 *   1. node:sqlite enables foreign keys by DEFAULT, and 15+ tables reference
 *      users(id) ON DELETE CASCADE. DROP TABLE users with foreign keys ON
 *      cascade-deletes most of the database. Hence PRAGMA foreign_keys = OFF.
 *   2. PRAGMA foreign_keys is a silent no-op inside a transaction, so it must be
 *      set before BEGIN. Hence ownTransaction = true.
 *
 * The copy uses an EXPLICIT column list, not SELECT *. The pre-existing
 * `applications` rebuild in db.js used SELECT *, which works only while column
 * order matches exactly — and column order here depends on the order historical
 * addColumnIfMissing() calls happened to run on that particular database.
 */

export const EXPECTED_USER_COLUMNS = [
  'id', 'name', 'email', 'password_hash', 'grade', 'role', 'verified',
  'avatar', 'bio', 'school', 'skills', 'leaderboard_opt_in', 'username',
  'profile_visibility', 'created_at', 'token_version', 'email_opt_out',
  'account_status', 'deleted_at', 'email_verified', 'username_changed_at',
];

function up(db) {
  // Already rebuilt? The CHECK text is the cheapest reliable probe.
  const existing = db.prepare("SELECT sql FROM sqlite_master WHERE type='table' AND name='users'").get();
  if (existing?.sql?.includes("'super_admin'")) return;

  // Guard: if this database has columns this migration doesn't know about, the
  // explicit copy below would silently DROP them. Fail loudly instead.
  const actual = db.prepare('PRAGMA table_info(users)').all().map(c => c.name);
  const unknown = actual.filter(c => !EXPECTED_USER_COLUMNS.includes(c));
  const missing = EXPECTED_USER_COLUMNS.filter(c => !actual.includes(c));
  if (unknown.length) {
    throw new Error(
      `users has unexpected columns [${unknown.join(', ')}]. Add them to `
      + 'EXPECTED_USER_COLUMNS and to the CREATE TABLE below, then re-run. '
      + 'Copying without them would delete that data.'
    );
  }
  if (missing.length) {
    throw new Error(
      `users is missing expected columns [${missing.join(', ')}]. `
      + 'initDatabase() must run its addColumnIfMissing() pass before migrations.'
    );
  }

  const cols = EXPECTED_USER_COLUMNS.join(', ');
  const fkWasOn = db.prepare('PRAGMA foreign_keys').get().foreign_keys === 1;

  db.exec('PRAGMA foreign_keys = OFF');       // MUST be outside the transaction
  try {
    db.exec('BEGIN');
    try {
      db.exec(`
        CREATE TABLE users_new (
          id TEXT PRIMARY KEY,
          name TEXT NOT NULL,
          email TEXT UNIQUE NOT NULL,
          password_hash TEXT NOT NULL,
          grade TEXT CHECK(grade IN ('9', '10', '11', '12', 'Adult', 'N/A')) NOT NULL,
          role TEXT CHECK(role IN ('student', 'organizer', 'admin', 'super_admin', 'partner')) NOT NULL,
          verified INTEGER DEFAULT 1,
          avatar TEXT,
          bio TEXT,
          school TEXT,
          skills TEXT,
          leaderboard_opt_in INTEGER DEFAULT 0,
          username TEXT UNIQUE,
          profile_visibility TEXT CHECK(profile_visibility IN ('private', 'friends', 'public')) DEFAULT 'private',
          created_at TEXT NOT NULL,
          token_version INTEGER NOT NULL DEFAULT 0,
          email_opt_out INTEGER DEFAULT 0,
          account_status TEXT CHECK(account_status IN ('active', 'deleted', 'suspended')) DEFAULT 'active',
          deleted_at TEXT,
          email_verified INTEGER DEFAULT 0,
          username_changed_at TEXT
        )
      `);

      const before = db.prepare('SELECT COUNT(*) c FROM users').get().c;
      db.exec(`INSERT INTO users_new (${cols}) SELECT ${cols} FROM users`);
      const after = db.prepare('SELECT COUNT(*) c FROM users_new').get().c;
      if (before !== after) throw new Error(`Row count changed during copy: ${before} -> ${after}`);

      db.exec('DROP TABLE users');
      db.exec('ALTER TABLE users_new RENAME TO users');

      // DROP TABLE took the indexes with it. Recreate all three, matching db.js.
      db.exec('CREATE UNIQUE INDEX IF NOT EXISTS idx_users_username ON users(username) WHERE username IS NOT NULL');
      db.exec('CREATE UNIQUE INDEX IF NOT EXISTS idx_users_username_nocase ON users(username COLLATE NOCASE) WHERE username IS NOT NULL');
      db.exec('CREATE UNIQUE INDEX IF NOT EXISTS idx_users_email_nocase ON users(email COLLATE NOCASE)');

      const violations = db.prepare('PRAGMA foreign_key_check').all();
      if (violations.length) {
        throw new Error(`${violations.length} foreign key violations after users rebuild`);
      }

      db.exec('COMMIT');
    } catch (err) {
      db.exec('ROLLBACK');
      throw err;
    }
  } finally {
    if (fkWasOn) db.exec('PRAGMA foreign_keys = ON');
  }
}

export default { version: 1, name: 'authz_roles', ownTransaction: true, up };
```

```js
 * Per-user capability grants.
 *
 * Exists so a job title does not become a role. An NHS advisor is usually also a
 * teacher and sometimes an organizer; adding a role per title multiplies the
 * authorization matrix for no benefit. A scoped, expirable, audited grant is the
 * cheaper primitive.
 */
function up(db) {
  db.exec(`
    CREATE TABLE IF NOT EXISTS user_capabilities (
      user_id    TEXT NOT NULL,
      capability TEXT NOT NULL,
      scope      TEXT NOT NULL DEFAULT '',   -- '' = global; else school/event id
      granted_by TEXT NOT NULL,
      granted_at TEXT NOT NULL,
      expires_at TEXT,
      PRIMARY KEY (user_id, capability, scope),
      FOREIGN KEY(user_id) REFERENCES users(id) ON DELETE CASCADE
    )
  `);

}
```

> KEY, and SQLite treats NULLs as distinct in a unique index — so a NULL scope

```js
import { ALL_CAPABILITIES, SUPER_ONLY } from './authz.js';

const SUPER_ONLY_SET = new Set(SUPER_ONLY);

export function grantCapability({ db, userId, capability, scope = '', grantedBy, expiresAt = null }) {
  if (!ALL_CAPABILITIES.includes(capability)) {
    throw new Error(`Unknown capability: ${capability}`);
  }
  if (SUPER_ONLY_SET.has(capability)) {
    throw new Error(`Capability ${capability} cannot be granted — it is super_admin only`);
  }
  db.prepare(`
    INSERT INTO user_capabilities (user_id, capability, scope, granted_by, granted_at, expires_at)
    VALUES (?, ?, ?, ?, ?, ?)
    ON CONFLICT(user_id, capability, scope) DO UPDATE SET
      granted_by = excluded.granted_by,
      granted_at = excluded.granted_at,
      expires_at = excluded.expires_at
  `).run(userId, capability, scope, grantedBy, new Date().toISOString(), expiresAt);
}

export function revokeCapability({ db, userId, capability, scope = '' }) {
  db.prepare('DELETE FROM user_capabilities WHERE user_id = ? AND capability = ? AND scope = ?')
    .run(userId, capability, scope);
}

/** Unexpired capabilities held by this user, for `principalFor()`. */
export function grantsFor(db, userId) {
  return db.prepare(`
    SELECT DISTINCT capability FROM user_capabilities
    WHERE user_id = ? AND (expires_at IS NULL OR expires_at > ?)
  `).all(userId, new Date().toISOString()).map(r => r.capability);
}
```

```js
/**
 * The only authorization primitive route files may use.
 *
 * Must be mounted AFTER authenticateToken, which is what populates
 * req.principal. A missing principal is a 401 (not authenticated), never a 403,
 * because the two mean different things to a client: one says "sign in", the
 * other says "you cannot do this".
 */
export function requireCap(capability) {
  if (!ALL_CAPABILITIES.includes(capability)) {
    // Thrown at module load, not per request, so a typo fails the boot and the
    // test suite rather than quietly 403ing in production.
    throw new Error(`requireCap: unknown capability '${capability}'`);
  }
  return function capabilityGate(req, res, next) {
    if (!req.principal) return res.status(401).json({ error: 'Access token required' });
    if (!can(req.principal, capability)) return res.status(403).json({ error: 'Access denied' });
    return next();
  };
}
```

```js
/**
 * Client mirror of the server capability table.
 *
 * Re-exported from the server module rather than copied, because two copies of
 * an authorization table drift, and the direction they drift in is "the UI shows
 * a button the API rejects".
 *
 * This is UX only. Every capability is re-checked server-side; hiding a control
 * here is a convenience, never a security boundary.
 */
import { can as decide, principalFor, CAPABILITIES, SUPER_ONLY, ROLES, ALL_CAPABILITIES } from '../server/authz.js';

export { CAPABILITIES, SUPER_ONLY, ROLES, ALL_CAPABILITIES };

/** `user` is the object from /api/users/me — `{ id, role, … }`. */
export function can(user, capability) {
  if (!user) return false;
  return decide(principalFor({ id: user.id, role: user.role }, { grants: user.grants || [] }), capability);
}
```
