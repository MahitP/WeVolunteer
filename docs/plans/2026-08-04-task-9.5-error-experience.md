# Task 9.5 — The Error Experience

Status: built and verified
Supersedes: the board-only error pages shipped in `471268c` / `2b015d3`

---

## 1. Research: why the good ones work

I inspected GitHub's live 404 in a browser, and read published craft analysis
(Smashing Magazine's *101 Course on Crafting 404 Pages*, IxDF). Stripe, Linear,
Vercel and Notion redirect anonymous traffic to a login or render an empty SPA
shell, so those are reasoned from design principle and prior knowledge rather
than from a live inspection — worth stating plainly rather than implying I saw
all fifteen.

Seven principles came out of it. They are the actual brief for everything below.

**1. A scene, not a notice.** GitHub puts the Octocat on Tatooine — sky, dunes,
a sandcrawler, a horizon. There is foreground, midground and background. A
centred card has no *place*; it is a dialog box with better typography. Depth is
most of what separates "designed" from "handled".

**2. The copy lives inside the composition.** GitHub's line sits in a speech
bubble belonging to the character. That one move converts a system message into
somebody *saying* something. Voice requires a speaker — a headline floating
above an illustration is still a system talking.

**3. The scene gets the attention; the exit gets the space.** GitHub's search
sits below the band in a calm strip. Weak error pages invert this: a giant "Go
home" button and a tiny sliver of personality. The way out must be obvious and
quiet, never the loudest thing on screen.

**4. Restraint reads as confidence.** The Stripe/Linear tier leans on
typography, spacing and one exact gesture rather than illustration density.
Anything that looks like it is *trying* to be liked is already failing.

**5. Humour is character-based, not joke-based.** "This is not the web page you
are looking for" works because a Jawa-costumed cat delivers it. The costume does
the work. The same sentence with no speaker is a dad joke — which is precisely
the failure mode of most "funny" 404s.

**6. Tone must scale with stakes.** A dead link costs nothing, so play. A 500
may mean lost work, and a joke told at that moment reads as the company not
understanding what just happened to you. This is the single most-violated rule
in the category and the one this system enforces structurally (§5).

**7. It could not belong to anyone else.** You cannot swap GitHub's 404 onto
Stripe. That is the real bar — not "is it attractive" but "is it *ours*".

### What this rules out

The brief's forbidden list and principle 1 together kill the current design's
core layout: it is a **centred column**. Centred text is the default of every
error page ever made. Everything here is left-aligned on an asymmetric grid.

## 2. The three weights

Not every failure deserves a cinematic page. Using the wrong weight is its own
design failure — a fullscreen takeover for a widget that failed to refresh is
melodrama, and an inline toast for a fatal crash abandons the user.

| Weight | Component | Used for |
|---|---|---|
| **Fullscreen** | `ErrorExperience` | 404, 403, 500, crash, offline, expired, chunk, maintenance |
| **Panel** | `ErrorPanel` | API unavailable, feature unavailable, in-context permission denial, a section that failed to load |
| **Inline** | existing `alert` / toast | validation, retry banners, per-row failures |

Inline is deliberately left alone. It already works, `Toasts.jsx` just gained
its assertive-vs-polite fix in `2f5ed75`, and rebuilding it would be change for
its own sake.

`ErrorPanel` shares the copy layer and the theme's palette but renders a compact
composition — no full scene, no stage. It replaces `ErrorBoundary`'s current
fallback, which uses a `lucide` `AlertTriangle`: a warning triangle and a
floating stock icon, two items from the forbidden list, in the one component the
whole app falls back to.

## 3. Error kinds

The canonical set. Every kind is a distinct *situation*, not a distinct status
code — `crash`, `chunk` and `500` are all "our fault" but they need different
words, because what the user should do about them differs.

| Kind | Situation | Wired from |
|---|---|---|
| `404` | route not found | router catch-alls |
| `403` | permission denied | `denied` element in App.jsx |
| `500` | server failure | server error responses |
| `crash` | unexpected client exception | both `ErrorBoundary` fallbacks, via `kindForError` |
| `chunk` | a lazy route's bundle failed | the same, via `kindForError` |
| `offline` | no network | `useOnline` + `OfflineOverlay` (§7) |
| `expired` | session ended | **no producer yet** |
| `maintenance` | planned downtime | **no producer yet**, by design |

`chunk` and `crash` come from the same place and are told apart by
`kindForError(error)` in `kinds.js`, which matches the three engine wordings for
a dynamic import that failed. It shipped unwired first — every caught error was
reported as `crash` — which meant the commonest failure in a deployed SPA, a tab
left open across a release, was described as a crash and offered a boundary
`reset` that cannot fix a file that is no longer on the server. `chunk` passes
no `onRetry`, so its action is a reload, which can.

`expired` and `maintenance` ship with copy, artwork and eligibility and nothing
that triggers them. `maintenance` is deliberate — the brief asked for "future
ready" and a kind costs nothing until a server flag needs it. `expired` is
**deferred, not designed away**: it needs 401 handling in the api layer, which
is a change to a different subsystem than this task owns.

## 4. The themes

Six. Each is a **place inside school volunteering**, not a visual treatment —
that is what keeps rotation from feeling like six wallpapers on one design. Each
has its own composition, motion signature and voice.

| id | Theme | The place | Motion signature |
|---|---|---|---|
| `board` | The Bulletin Board | corkboard of pinned signup sheets | papers breathe; one flutters loose |
| `map` | The Campus Map | wayfinding map, dotted walking route | the route draws itself; a pin bobs |
| `desk` | The Front Desk | check-in table, lanyard, name tags | the badge swings on its lanyard |
| `ops` | The Ops Wall | organiser's event status strips | strips pulse; one flickers out of step |
| `radio` | The Radio Room | volunteer dispatch handset | signal rings travel outward; one breaks |
| `fair` | The Club Fair | booths with bunting, one empty | bunting sways; a card tips |

All six are community, events, clubs, students, service. None is sci-fi. `ops`
and `radio` are the closest to "technology" and are deliberately warm — an ops
wall of paper strips and a walkie-talkie, not a NASA console.

### Eligibility

A theme appears only where it is *honest*. A radio room does not explain a
permission refusal; a lanyard desk does not explain a server fault.

| | 404 | 403 | 500 | crash | chunk | offline | expired | maint |
|---|---|---|---|---|---|---|---|---|
| `board` | ● | ● | ● | ● | ● | | | ● |
| `map` | ● | ● | | | | ● | ● | |
| `desk` | | ● | | | | | ● | |
| `ops` | | | ● | ● | | | | ● |
| `radio` | | | ● | | ● | ● | | ● |
| `fair` | ● | | | | | | | ● |

`board` is the universal fallback and covers every kind that has no other
natural home. Every column has at least one mark — asserted by a test, not by
this table.

### One kind, one picture

Eligibility decides *whether* a theme may answer a kind. A second rule decides
whether it has anything new to say: **no theme may map two kinds to the same
mode**, and `selector.test.js` fails the build on it.

That rule exists because the first version broke it badly. `board` claimed six
kinds and drew three pictures — `500`, `crash`, `chunk` and `maintenance` were
all mode `rebuild`, so four cards in the contact sheet were pixel-identical.
`radio` had four kinds and two pictures, `ops` three and two. Twenty screens on
paper, fourteen drawings on screen. Breadth of rotation is worth nothing if the
pictures repeat: a reader recognises the drawing long before they read the
headline meant to distinguish it, and the whole thing reads as one design in
hats — precisely what this system exists to avoid.

Six modes were added rather than a seventh theme: `board/torn`, `board/partial`,
`board/notice`, `ops/dropped`, `radio/garbled`, `radio/scheduled`. Depth where
the repetition was, rather than width for its own sake.

`map/unmapped` is the one addition that widens instead: a map whose far half
never arrived is what everyone with a phone has already seen when their signal
dropped, so it explains `offline` without borrowing a metaphor — and `offline`
had exactly one eligible theme before it.

## 5. Copy

Copy lives with the theme, not with the kind: "the sheet wandered off the board"
only makes sense beside a corkboard. Split them and rotation immediately feels
like one design wearing hats.

**The tone ladder is structural.** `404`, `403`, `chunk` and `maintenance` carry
personality. `500`, `crash` and `offline` are written flat, and `expired` is
written plainly because the user is about to lose what they typed. This is
principle 6 from the research, encoded as a rule rather than left to taste — and
a test asserts that every serious kind's copy contains the reassurance and none
of it contains an exclamation mark.

Every 500/crash copy leads with *your data is safe*, because that is the actual
question the person has.

---

## 6. Rotation

**Store a seed, never a theme name.** A session that hits 404 and later 500
would break a stored name outright — `fair` is not eligible for 500. An integer
seed indexes into the eligible list *for the kind being rendered*, so the
personality stays consistent across a session while every screen stays honest.

```
seed    = sessionStorage['wv-error-seed'] ?? mint-and-store
theme   = eligibleFor(kind)[seed % eligibleFor(kind).length]
```

Failure modes, all handled and all tested: storage that throws (Safari private
mode) falls back to a module-level seed so the session is still stable; a
corrupt or non-numeric stored value is re-minted; an empty eligible list cannot
happen but returns `board` anyway, because a fallback never exercised is not a
fallback.

Themes are **statically imported, not lazy**. Six small SVG/CSS components are
cheaper than the Suspense boundary needed to defer them, and a spinner on an
error page is the exact "user should not notice loading delays" failure. There
is no SSR here, so no hydration concern; selection is a lazy `useState`
initialiser so re-renders never reshuffle.

## 7. Architecture

```
src/views/ErrorExperience/
├── ErrorExperience.jsx     the frame — owns ALL behaviour
├── OfflineOverlay.jsx      covers the app without unmounting it
├── ErrorPanel.jsx          the medium weight
├── ErrorGallery.jsx        the contact sheet, DEV only
├── selector.js             seed + eligibility + fallback
├── errorCopy.js            COPY[theme][kind]
├── kinds.js                kind list, tone ladder, kindForError()
└── themes/
    ├── index.js            registry: id → { id, Scene, kinds }
    └── BoardScene.jsx  MapScene.jsx  DeskScene.jsx
        OpsScene.jsx    RadioScene.jsx  FairScene.jsx
```

**The frame owns everything that can be got wrong. Themes own only pixels.**
`role="alert"`, the `aria-labelledby` heading wiring, focus, the product mark,
the session-dependent actions and the no-leak guarantee live in
`ErrorExperience.jsx` exactly once. A `Scene` is a pure presentational component
that receives `kind`, returns artwork into an `aria-hidden` slot, and can reach
nothing else — no router, no session, no props beyond `kind`.

That boundary is the reason six themes do not mean six chances to reintroduce
the redirect bug, and it is enforced by a test that renders every theme through
the same behavioural suite.

`ErrorPage.jsx` is deleted and App.jsx's four references updated. A re-export
shim is exactly the dead weight `noDanglingClasses` exists to discourage.

### New behaviour: `useOnline` + `OfflineOverlay`

The app had **no network detection at all** — `navigator.onLine` appeared
nowhere. `offline` therefore needed a producer, not just a picture: a small hook
over the `online`/`offline` events, no dependency.

**Offline COVERS the app; it does not replace it.** The first wiring chose
between the experience and the routed view with a ternary, which reads as a
display decision and is really a destruction — React unmounts the subtree, so
everything unsaved inside it is gone. Measured in a browser: a name typed into
`/signup`, a synthetic `offline` then `online`, and the field came back empty,
under copy promising "anything you haven't sent is still on this device". A
dropped bar on a school bus lasts seconds and must cost nothing.

So the shell stays mounted under an opaque fixed overlay, `inert` and
`aria-hidden` while it is covered, and comes back untouched — mid-sentence —
when the connection does. `inert` and not merely `aria-hidden`: the latter hides
the app from a screen reader and leaves every control in it tabbable, behind an
opaque cover, with no visible focus.

It wraps the **whole shell**, not just `<main>`. An overlay is opaque, so any
nav left outside the wrapper is a tab stop nobody can see.

`useOnline`'s own header says `navigator.onLine` is used "to explain a failure
the app already met, never to predict one". Covering rather than replacing is
what keeps the wiring honest to that: nothing is destroyed on the strength of a
signal that only reliably reports the absence of an interface.

## 8. Constraints this lives inside

Unchanged, and all three static guards still apply:

- `tokens.test.js` — every `var(--x)` must exist in `index.css`, no allowlist.
  SVG fills use `var()`, so themes theme automatically.
- `noHardcodedColors.test.js` — no colour literal under `src/`. Every scene is
  token-only.
- `noDanglingClasses.test.js` — no class without a rule, no rule without a
  reference.

No new dependency. No asset. `lucide-react` is already present and is used only
for genuine UI affordances in the actions row, never as artwork.

## 9. Testing

- **Behaviour is parameterised across all six themes.** No-leak, `aria-hidden`
  artwork, one `h1`, actions matching session and kind, no inline animation —
  every one runs six times. These are properties of the system, not of a theme.
- **Selector, including mutation tests.** Determinism for a fixed seed;
  eligibility respected (never `fair` for a 500); spread across seeds so a
  selector that always returns index 0 fails; storage-throws path; corrupt-value
  path; every kind resolvable.
- **Two new static guards.** Every animated `.err-*` class must appear in a
  `prefers-reduced-motion` block with `animation: none` — generalised from the
  current hand-listed four, so theme seven cannot ship unmuted. And every
  `.err-*` class referenced in JSX must have a rule, and vice versa.
- **Tone ladder.** Serious kinds carry the reassurance; no serious copy contains
  an exclamation mark.
- **Rotation-independence at the App level.** The nine assertions in
  `App.routeTable.test.jsx` and `App.authRoutes.test.jsx` currently hardcode the
  board's headlines and would become seed-dependent — flaky in exactly the way
  TD-9 was. They move to `data-error-kind`, which is stable across rotation,
  absent from `textContent` so the no-code-in-copy rule is untouched, and makes
  them assert the routing claim they were always making.

## 10. Browser verification

Done in a real browser, at desktop and 375px, in light and dark. It found six
defects that every test in the suite was green through — worth listing, because
they are all things only looking catches:

1. **The wash gave the whole app a horizontal scrollbar on a phone.**
   `.err::before` is inset negatively so the light feels bigger than the box;
   unclipped that made the document 398px wide in a 375px viewport. The symptom
   surfaced somewhere else entirely — `.toasts` is absolutely positioned, so it
   stretched to the widened document and looked like the culprit. Fixed with
   `overflow: clip` on the stage.
2. **The radio's signal rings escaped the frame**, drawing across the page
   outside the scene: r=160 through -90° put the outer arcs at y=-27, and
   `.err-scene` is `overflow: visible`. Re-derived the geometry so every ring
   lands inside the viewBox, and pinned the constraint in a comment.
3. **The ops wall's five strips overflowed their own panel** by 13px.
4. **The map's barrier stripes rendered outside the barrier.** `skewX`
   translates by `y·tan(angle)` about the origin, so at y≈96 they were displaced
   31px left. Restated as explicit parallelograms, bounded by construction.
5. **The board's loose sheet crossed the bottom of the viewBox.** Fixed by
   nesting it: the outer group carries the static lift, the inner one carries
   the flutter — they cannot be the same element, because CSS `transform` and
   the SVG `transform` attribute are one property and the keyframe silently
   drops the offset.
6. **The board and map dissolved into the page in light mode.** Their back
   planes had no edge and the wash behind the board was at 0.9. Added a border
   to the scene planes and dropped the board's wash to 0.42.

Also confirmed: the offline experience appears on a synthetic `offline` event
and **removes itself with no interaction** when the connection returns, which
is the promise its own copy makes; scenes stack above the copy at 375px with
the text still left-aligned; `aria-labelledby` resolves to the `h1`; the stage
is `aria-hidden`; and focus order is copy → actions.

Reduced motion is asserted statically rather than by eye, in
`src/errorStyles.test.js` — jsdom does not apply media queries, and the browser
cannot prove the *absence* of an unmuted future theme. The guard derives the
animated selector list from the stylesheet, so theme seven fails the build if it
ships without an opt-out.

## 11. Second pass — pre-commit review

The whole system was re-read as a senior review before anything was committed.
Three defects, two of them reproduced in a browser rather than reasoned about.

**1. A connection blip destroyed unsaved input.** Covered in §7. Proven by
typing into `/signup`, firing a synthetic `offline` then `online`, and reading
the field back: `"Jordan Alvarez"` → `""`. Fixed with `OfflineOverlay`;
re-measured after the fix, the value survives, and four mutants of the overlay
(revert to the ternary, drop `inert`, drop `aria-hidden`, never render) are each
killed by its tests.

**2. A theme froze at the first kind the component ever saw.** The theme was
pinned in a `useState` lazy initialiser, so a prop change repainted nothing:
moving the gallery from `radio/offline` to `ops/500` client-side kept the radio
on screen, and only a hard reload agreed with the URL. The quiet version of the
same bug is worse — `copyFor` reads the live kind while the scene comes from the
dead one, so a permission refusal can be narrated over a server-fault picture.
`useMemo` is both the fix and the simpler code: `selectTheme` is deterministic
given a seed that is already persisted, so nothing was being protected by state.

**3. `chunk` had no producer.** Covered in §3.

Also removed: `ErrorPanel`'s `fault`/`denied`/`quiet` tones. No caller ever
passed one, so two of the three were unreachable, and `errorStyles.test.js` had
to allowlist their class names to stay green — a guard working around the code
rather than checking it. A prop with one possible value is not an API.

### Measured

- **Bundle.** The experience adds **24.7 kB raw / 7.1 kB gzip** to the eager
  entry chunk (113 kB gzip). Kept eager deliberately: an offline or
  chunk-failure screen that needs a network fetch to render is not a fallback.
- **`ErrorGallery` does not ship.** Verified against `dist/` — no gallery string
  appears in any built asset, while the scene copy does.
- **`stroke-dashoffset`** (`err-march`, `err-march-slow`) is the one motion here
  that is not compositor-accelerated, so it repaints on the main thread for as
  long as the page is open. Contained to two short paths and accepted; noted
  because it is the first thing to look at if an error screen ever feels heavy
  on a low-end Chromebook.

### Browser verification, second pass

Every new mode was reviewed at desktop width in both themes. Two defects that no
test could have caught, both found only by looking:

1. **The torn sheet folded into a zigzag sliver.** The outline reaches the tear
   having just come down the right edge, so the ragged points have to be walked
   right-to-left; traced left-to-right they jump back across the sheet. Nothing
   about the path is invalid — it simply drew the wrong shape.
2. **The maintenance notice was transparent.** `--warn-tint` is a low-alpha
   colour, so the pinned sheets read straight through the card and it looked
   projected rather than taped on. Fixed with an opaque backing beneath the
   tint; the tape was lifted to full opacity for the same reason.

A third was caught by reasoning about paint order and confirmed on screen: the
fallen ops strip was drawn in its own row, so the rows below painted over it and
it looked like a wedge sliding underneath. It now empties its slot and is drawn
last, on top, where the thing that fell belongs.

A fourth came from measuring rather than looking, and would not have been found
by either reading the code or squinting at it — the radio's wash ellipse was
`cy=176 ry=126`, so its bottom edge was at y=302: past the 300-unit viewBox and
16 past the panel's own edge, with `.err-scene` set to `overflow: visible`. A
soft glow was painting outside the card on all four radio screens.

### The check that found it, and why it is not a test

Every scene's content must stay inside its own `0 0 400 300` viewBox — the
frame is `overflow: visible`, so anything outside it draws across the page.
Run on the contact sheet:

```js
[...document.querySelectorAll('svg.err-scene')].filter(s => {
  const b = s.getBBox();
  return b.x < -1 || b.y < -1 || b.x + b.width > 401 || b.y + b.height > 301;
}).map(s => `${s.classList[1]}/${s.dataset.mode}`)
```

It cannot be a unit test: `getBBox` needs a real layout engine and jsdom does
not implement it. `tests/e2e/` could host it, but `@playwright/test` is not a
dependency and adding one for this is not a trade worth making. So it is written
down here as a step, not pretended into the suite — the honest version of a
check that cannot be automated with what the repo has.

Currently clean: 21 scenes, 0 escapes, and no horizontal document scroll at
either 1280px or 375px.

### Deliberately not covered by the offline overlay

The auth-flow paths (`/reset-password`, `/oauth/callback`), the public
certificate route (`/verify/*`) and the session-check skeleton all return before
the shells that `OfflineOverlay` wraps. Each is reached by a link from outside
the app and should render whatever it can rather than be replaced wholesale.
Extending the cover to them is a deliberate non-goal here, not an oversight.
